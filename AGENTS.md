# Agent Guide

Read `README.md` first.

- `profile/README.md` is generated by the vendored shared renderer. Change
  `profile/catalog.json`, run `python3 Scripts/render-profile.py`, and commit
  both. Do not edit the vendored Python files in `Scripts/vendor/` by hand.
- `.github/workflows/presentation.yml` checks caller terminal scripts against
  the uploaded executable on the caller's build OS. Keep DESIGN and fonts
  bound to the standard at `job.workflow_sha`, and use the same pinned
  toolchain Action for DESIGN lint. Its CI self-test uses
  `Tests/Fixtures/Presentation`; regenerate its recording and both SVGs with
  the pinned toolchain as described in the fixture README.
- Keep catalog membership equal to the organization's public, non-archived
  repositories except `.github`; `python3 Scripts/check` verifies it against
  GitHub.
- Repository summaries state what the repository does for a visitor, in one
  sentence, from that repository's current behavior.
- `DESIGN.md` owns the organization's visual tokens (Google DESIGN.md format,
  tokens in the front matter) and its icon entry. Read it before visual or asset
  work. After changing it, lint it (zero errors and zero warnings), copy
  changed values into the recipes that use them, update every recipe's
  `design_sha256`, and regenerate its listed outputs as described in
  `README.md`. Regenerate affected outputs after `Brand/Icon/`
  artwork changes; commit sources and outputs together.
- Run `python3 Scripts/check --offline`, `python3 Scripts/check`,
  `python3 -m unittest discover -s Tests`, `actionlint` (or parse every workflow
  as YAML if unavailable), and `git diff --check origin/master` before handoff.
  Report live drift and unknowns; checks never change settings.
